## Problem and resulting behavior

The closed-entry scanner currently interprets a four-byte window spanning two genuine instructions as a pointer into a protected predicate. The existing paired boundary certificate can distinguish this only for its older accepted R1 grammar. Add a generic connected native declaration binder that supplies actual instruction boundaries to that same certificate. A complete original Normal/Kernel pair can then pass this particular byte-ownership test; ordinary predicate, capacity, identity, final-pair and receiver checks still decide admission.

The source-bound positive window is ADD.W's immediate tail followed by LDM.L's opcode. Its CPU address, bytes, model, SAT label and hashes must not occur in production policy. No lookup table of exceptional images or offsets is permitted. Full real immediates and actual instruction references remain references.

## Static discovery algorithm

This is a bounded native grammar, not a C++ runtime/type theorem. It recognizes a connected declaration graph, with coordinates derived from the bytes. Register carriers are *declared formal carriers*. Opaque calls are retained as declarations and do not assert that runtime registers survive. Explicit local writes that change a carrier must break its local declaration relation. No call-return, scheduling or allocator analysis is performed.

1. Obtain an existing ClosedEntries unclassified four-byte literal diagnostic. Its observed position is a search seed, not an exclusion. Search complete ordinary H8 function prologues within at most4096 bytes before it, decode forward at most4096 bytes/2048 instructions, and retain only a complete body containing that window. Decode calls as instruction plus conditional continuation, without traversing callees; fork conditional branches, follow local direct branches/JMPs and stop at RTS. Reject indirect jumps, traps/return-exception/unclassified control, overlap, branch-to-interior, out-of-body non-call transfer, unexplained decoded holes and truncation. Every decoded instruction must be structurally reachable from the entry under those conditional call continuations. Do not infer execution or return from this graph.
2. Bind a direct caller from an actual complete caller body using the same bounded decoder. That caller must itself be an address-derived method-table entry in the graph below. Merely finding an aligned JSR byte sequence or a raw pointer is insufficient. Require one unambiguous connected declaration for the proposed body; ambiguous owners refuse.
3. Bind a child-constructor declaration: an entry formal parent carrier, an allocated/result child carrier, an immediate table address stored at a child vptr displacement, and publication of that child at a parent field displacement. The complete constructor must contain those decoded operations in one branch path; paths and conditional null results are retained, not assumed executed. The relevant pointer store and parent publication are explicit local instruction relations. Read the table function and adjustment slots only through the typed invocation in step5.
4. Bind the shared parent declaration: an adjacent direct getter→child-constructor call pair with no argument rewrite; the getter's explicit static-parent immediate and its parent-constructor call; that parent constructor's formal receiver and immediate worker-table store. The parent constructor calls its base initializer with an explicit descriptor. The base initializer declares a trampoline address in its native entry descriptor, and binds the actual descriptor-record call preparation: a descriptor-word argument and an SP-derived record argument. This is a static declaration of the record/call interface, not an assertion about Kernel-create effects. That trampoline contains the decoded object-vptr/function/adjustment indirect-call grammar. Use the actual vptr displacement and function/adjustment slot displacements from this grammar to read the worker-table entry. Thus the worker entry comes from a declared table slot, not an assumed table extent or nearby pointer. Allocator, Kernel-create and opaque diagnostic effects are outside this declaration proof.
5. In that worker, bind an explicit formal-parent carrier passed to a direct invoker call. The worker contributes a bounded entry-rooted declaration prefix, not a complete owned function: stop immediately after the first fully connected typed invoker call. Decode the actual entry-to-call instruction paths and internal branch targets with the same finite limits, rejecting incomplete instructions, overlap, branch-to-interior, unclassified control on the selected path, limit exhaustion and multiple incompatible connected candidates in the examined prefix. The selected path must contain the explicit formal-carrier assignment and no subsequent explicit local carrier overwrite; opaque calls remain declarations only. Do not start at an interior address, skip an unsupported prefix or search an unexamined tail to rescue a match. Branch exits beyond the selected cut remain unowned, and their bytes retain conservative raw-reference scanning. Protect all examined prefix instructions, but do not add the prefix or tail to the complete owner/caller ownership ranges or suppress any worker crossing window. This finite static edge does not require enumerating the rest of the worker; step1's complete-body requirement remains unchanged for the owner and step2's caller. In the invoker, bind the straight-line sequence loading the parent child field, the child's vptr, a function slot and adjustment slot, adding the child to its adjustment and invoking the loaded function. The parent field and child-vptr displacements must equal step3's publication/store coordinates. Read precisely these slots from step3's child table; the function entry must equal step2's complete caller. The function/adjustment loads and indirect call have no intervening unresolved control or explicit carrier rewrite. Prefix calls may preserve the static method declaration but do not grant a runtime preservation contract.
6. The shared-parent graph must be connected by these actual direct-call targets, table addresses, formal-receiver declarations and equal field coordinates. A matching displacement in an unrelated class is not evidence. Protect every decoded instruction span and table word used to establish this graph. Complete owner/caller bodies are protected in full. There is no requirement to execute the graph or prove that the captured current object uses this particular variant table.

Use existing H8 decoding and checked arithmetic; do not add a decoder or a general interprocedural interpreter. Pattern guards may restrict this native instruction/register form, while all addresses and object/table coordinates are operands. Limits refuse unsupported input rather than widening acceptance. If the implementation cannot express this exact connected grammar without a new semantic assumption, stop and return the specific seam; do not substitute a specimen byte array or address list.

## Interior references and crossing predicate

For each complete owned body, collect even addresses that are not instruction starts. Outside the owned caller/owner bodies, keep the existing conservative Normal/Kernel raw-reference grammar, including last complete two-byte relative tails. Within owned bodies, inspect the actual decoded control targets, absolute operands and full address immediates; operand bytes are not re-decoded as independent instructions. Reject references to any collected interior. A real entry at an instruction boundary is distinct from an interior and stays classified under its actual reference; this certificate does not prove all computed aliases absent.

A suppressible window has length4, starts strictly inside one owned instruction, crosses its end, and ends within its immediately adjacent owned instruction. Both complete instructions belong to the same accepted body and the actual bytes begin with the scanner's zero-byte literal form. No fixed window position/value is allowed. A full32-bit immediate fits inside one instruction and is never suppressed. Nonowned bytes, body tails and missing/ambiguous graphs are never suppressed.

Store all supporting spans in the existing certificate protection. `accepts_kernel` must recheck the entire actual final Kernel for newly introduced interior references. The existing Normal integrity/protected-span checks must bind the entire new graph, not only the collision bytes. No final-pair or original-authority check is relaxed.
