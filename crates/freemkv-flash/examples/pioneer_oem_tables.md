# Refreshing Pioneer OEM reconstruction metadata

These tables are optional archival metadata used by freemkv-flash backups. They
are not hardware compatibility lists and never authorize a flash. The generic
codec and receiver rules live in pioneer-optical.

From the workspace root, using an OEM-only collection of extracted `.enc` files:

```sh
cargo run --release -p freemkv-flash --example pioneer_oem_tables -- \
  /path/to/hoard/images/pioneer \
  crates/freemkv-flash/src/drive/pioneer \
  /tmp/pioneer-oem-refresh
```

Inspect `report.json` before copying `k.bin` and `n.bin` from the
output directory into `crates/freemkv-flash/src/drive/pioneer`. Run the flash tests and the
configured corpus/byte-exact regressions, then commit both tables with the source.
The executable embeds them at compile time; changing files beside an installed
executable does not update its metadata.

The generator:

- Recursively visits current `.enc` files, rather than depending on obsolete
  tar-only hoard paths. An empty collection or malformed existing table fails.
- Decodes H8 Kernels, checks image checksums, and recovers the complete OEM key
  from a verified encoding seed or the original front key.
- Pairs Normals with Kernels whose hardware, Kernel version and destination
  metadata agree. Decoding alone is insufficient: rebuilding with the recovered
  seed and original signature must equal the source file byte-for-byte.
- Chooses a deterministic canonical metadata record for duplicate decoded bodies.
  Existing canonical records remain stable. Historical entries whose sources are
  absent or outside current reconstruction support are retained and counted
  separately; they are not claimed as newly verified.
- Rejects the explicit zero-placeholder backup metadata and requires Normal
  authentication, so user captures in a mixed collection cannot become OEM rows
  merely by reconstructing their placeholder envelopes.
- Emits a per-file reason for exclusions. Unsupported architectures, failed
  checksums, unavailable keys or non-reproducible framing never receive guessed
  metadata. Review omissions rather than treating successful generation as
  proof that every held envelope is reconstructible.

The old tables were generated by private throwaway programs scanning
`hoard/pioneer` and `hoard/kernels/pioneer` tar files, using the former codec API.
Those directories no longer represent the collection. The XD06U 1.11 regression
exposed that the compiled snapshots had not kept pace with the current hoard.

The XD06U Normal regression always checks the embedded metadata. To also check
its complete generated envelope against the independently held original, set
`PIONEER_XD06_RECONSTRUCTION_FIXTURE` to a directory containing `backup-kernel.enc`,
`backup.bin` (decoded Normal), `held-kernel.enc` and `held.enc` (OEM Normal), then run:

```sh
cargo test -p freemkv-flash --lib xd06 -- --nocapture
```

No private firmware corpus is included in the public repository.
