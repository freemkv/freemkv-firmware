# 0.15.3 personal user-message audit

Reviewed by the primary coding agent from the English copy, cause classifier, operation boundaries and final GUI/CLI rendering paths. The review was not delegated. Automated tests supplement this source/copy review; they do not establish physical hardware behavior or a manual click-through on every operating system.

## Rules applied

- Known unsupported operations, read restrictions and cancellation are information; missing input needs action. Actual I/O failures and update uncertainty keep their stronger meanings.
- A backup read rejection is not a flash failure. A successful raw dump is not a complete or restorable backup.
- No-write claims require capability/progress evidence. Startup parameter mutation and firmware update entry are different boundaries.
- Generic report escalation is retained for unexplained faults, not automatically appended to expected limitations.
- A zero RPC-2 reset budget is real data. RPC-1 does not have that budget, so its zeroed fields are hidden. Malformed/failed reads are unavailable, never fabricated zeroes.
- Website modification capabilities come from the exact image's Modify report; family or native media support does not grant a modification.

## Other reviewed prompts and warnings

- Recovery family-bypass title, explanation, code and acknowledgement: explicitly risky and separate from ordinary Flash; bypass waives only family comparison. Settings/authentication/receiver gates remain mandatory.
- Without-backup consent: states the missing backup and possible inability to restore. Corrected the active CLI text that claimed the drive could never be rolled back. Decline leaves firmware unchanged; acceptance does not waive other checks.
- MediaTek Flash/Backup/Dump forms: show a neutral read-limitation note before operation. The automatic submit-a-dump suggestion is not promoted on MediaTek forms.
- Loaded-disc and open-tray guards: source sense/drive-state evidence is checked; no generic communication explanation replaces the cause.
- Origin unknown/unavailable, unsupported comparison and missing Kernel: describe absent evidence or unsupported input, not corruption. Unsupported comparisons no longer request a report by default and use informational severity.
- Integrity verdicts: an existing image failure is an input finding; generated-image self-verification is an internal generation failure. Both prevent writing an invalid generated artifact.
- Report description required/too long, size budget, latest-version gate, changed attachment, cancellation, successful receipt and unconfirmed receipt: checked independently from firmware results. Failed update lookup remains fail-open for reports.
- Successful flash report prompt: appears only with fully verified completion and no backup/dump attachment. It does not turn unverified or interrupted writes into success.
- Optional Info RPC/vendor settings failures: retained in diagnostics, no invented capability or zero-valued fallback in the primary result.
- Read-only worker faults versus writing worker interruption: final guidance follows available progress evidence; unknown possible writes stay uncertain.
- Existing technical legacy/inspection strings: reviewed as report/detail values or historical localization compatibility, not alternative authorization or current error classification.
- Embedded Pioneer adaptation errors: original identity missing is a conditional offline candidate, mismatch is refused; exact-byte/hash/registry faults cannot authorize an image. Empty registry and no matching profile preserve existing checks. Loader state cannot skip original-hardware prerequisites.

## Regression evidence

- Reproduced WH16NS58 1.V5 read behavior: 64 KiB readable, lower reads rejected with 05/24/00. Notice copy, no cable diagnosis, no automatic report demand, no firmware write.
- Actual disconnect and mixed/short-read evidence retain failure guidance; the absence of bytes alone is not proof of a firmware restriction.
- MediaTek note appears before Flash/Backup/Dump and is absent on non-MediaTek forms. The primary agent visually inspected native macOS captures with the exact note on all three forms: readable neutral text and visible action buttons. All 247 native checks passed; the QA driver injects this note into its synthetic profile on every platform without drive I/O.
- RPC-1 hides user/vendor budgets and lock state; RPC-2 retains real zero counts and the supplied four/four example.
- Existing uncertainty/rollback/verification tests protect the write boundaries and remain release gates.
- No production adaptation JSON profiles; synthetic fixture is test-only. Full catalogue parity passed for all 807 exact packages: 22,841 admitted directed links and 416 future-candidate links are identical to both 0.15.2 and the published website graph.

## Follow-up after this release

Audit every Modify hook across every held firmware layout, starting with the WH16NS58 1.V9 descriptor-classifier UHD path. Full-hoard successful generation and integrity checks are not proof of semantic equivalence or hardware acceptance outside the tested BU40N configuration.
