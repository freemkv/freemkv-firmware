# 0.14.1 release evidence

The Windows reports in `logs.zip` and report
`97d4ac8d-be0b-45a0-8a54-78bcbf7f4aee` contain the same four operation logs.
The selected WH16NS58 1.V9 OEM reference passes receiver binding. Execution
stops during backup with only 65536 of 2097152 bytes readable. No firmware
write command was sent. The native GUI had inherited the confirmation trait's
default No instead of presenting the engine's backup-waiver question.

## Changes and evidence

- All shells now present explicit Yes/No backup consent. A dropped GUI or answer
  channel declines. Yes leads to a separate final Flash confirmation with a
  fresh, unchecked risk acknowledgement. No stops before execution.
- The optical backend owns `can_read`; Flash and Recovery hide automatic
  acquisition and require a Current file when that capability is false. Refresh
  preserves a manual choice. Backend identity, rather than model spelling,
  selects the capability. Both published optical crates are pinned to 1.0.0.
- Customer error classification retains typed failure evidence and full source
  chains in English diagnostics. Optional information read failures show
  Unavailable; their full failures are logged. Historical 0.11.2 transcripts are
  unchanged. HUMAN_ERRORS records the exact intentional presentation changes.
- Background firmware analysis and origin checks retain their full English causes.
  Their existing log controls can export in-memory diagnostics when a saved file
  is unavailable; old operation logs cannot hide the new failure.
- Flash and Modify share 29 catalogs with 555 entries each. Tests require equal
  key sets, nonempty values, exact placeholders, preserved product names,
  persistence, language changes, parameter/data preservation and English logs.
  Existing report providers retain English exports; a catalog adapter translates
  complete legacy report sentences at the display boundary.
- The first translation pass was machine assisted. Backup questions and read
  restriction explanations, and the required Current-file instruction, received
  manual corrections in all supported languages. This is not a claim of fluent
  human review of every translation.
- Diagnostic actions use one row in View/Save/Submit order. Only the drive family
  remains above the task tabs. A rendering test checks the action-row geometry.

The actual AppKit gate passed 115 checks, including every language menu,
all tabs, final-confirmation acknowledgement, the backup Yes/No dialog, hidden
extra checkbox and Return selecting No. AppKit reassigns a default button while
presenting an alert; the safe keyboard assignment is applied after presentation.

The full locked all-target/all-feature workspace run passed 1053 tests. Subsequent
localization/plan-label tests passed with 174 Flash GUI and 7 Modify GUI tests.
Warning-free all-target/all-feature Clippy and formatting passed. QA additionally
checks the native Windows/Linux shells and every release package before promotion.

## WH16NS58 1.V9 patching

OEM SHA-256:
`97b287072e20c9527de6f34f6d564c8edcc6afb3ecf5675c11b8262c11663061`.
The reported build also skipped Raw Read after running out of small injection
holes. Its final erased run crosses an active CMAC boundary; the allocator had
rejected the whole run instead of using its covered portion.

The allocator preserves existing full-run placements, then considers aligned
intersections wholly inside one active integrity range. Boundary, inactive-range,
headroom and existing-placement tests pass. The committed 1.V9 regression fixture
now installs Raw Read (including the fallback stub at 0x1b236c), passes the
structural audit and all CMAC checks, and supports editing its startup record
without reinjecting hooks. Existing BU40N known-answer tests remain unchanged.

These are software and mock-drive results. No physical drive was flashed during
this verification; controller programming and transport reliability still require
physical confirmation.
