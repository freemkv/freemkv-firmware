# 0.14.3 release evidence

Pioneer Dump now has a registry fallback for complete, printable, nonblank F1
hardware identities from a Pioneer vendor. Existing OEM backend probes run first.
The fallback exposes only the existing Dump facet; it does not offer Backup,
Flash, file recognition or Recovery. Recovery identification remains independent.
The dump implementation, command map, limited write grant and artifact format are
unchanged from 0.14.2.

Regression tests first reproduced the REC 8301/8800/8C00 classification refusal,
then verified that these identities reach memory capture and save the returned
bytes. Other tests retain malformed/unrelated-identity refusals, OEM update
restrictions, Recovery behavior and the existing release transcript checks.
These tests simulate device responses; physical REC read coverage is unverified.

The GUI offers a raw dump from the Backup screen when Backup is unsupported or
has failed. The resulting operation retains Dump identity and offers Submit Dump.
Completed Backup offers Submit Backup. Report bundles carry the selected file,
SHA-256, filename and byte count alongside the selected history and diagnostics.
Browser approval and the 50 MiB report limit still apply. The submission controls
and review guidance have translations in all supported UI languages.

The Pioneer Normal reconstruction metadata adds 32 authenticated SAT image
matches, increasing the catalog from 459 to 491. An offline production-builder
replay rebuilt all 491 eligible audited hoard Normal images. This does not add
ATA, SCSI or REC OEM envelope construction, nor certify hardware restoration.
The MediaTek catalog is unchanged.

Release follows dev CI, QA including native release tests and package checks,
then main CI and the v0.14.3 release workflow. The website approval disclosure and
reviewed Flash changelog accompany publication.
