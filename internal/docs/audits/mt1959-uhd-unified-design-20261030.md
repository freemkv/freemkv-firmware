# Unified MT1959 conversion design — 2026-10-30

Status: research design for review and implementation toward 0.16.0, based on firmware f5b7f12 and dependency 66c4b1c. This document changes no production code. Main development remains clean 0.15.4; MT1939 work remains deferred until the old-24 checkpoint. No flash or hardware outcome is claimed.

The implementation target is a source-qualified MT1959 media conversion with preserved native DVD/BD behavior and explicit authentication scope. Implement the known software corrections now; do not wait for unavailable physical proof to repair demonstrable helper defects. Conversely, neither six labels nor local CPU successes justify announcing that all UHD discs or factory playback work. The old-image installer remains atomic until its complete software contract is qualified. This is a conservative engineering policy, not proof that every reference difference is physically necessary.

## Patch architecture and exact obligations

Each plan binds an immutable source hash, recognized instruction bytes, real state pointers, relevant literal/table ownership, hook entry, overwritten instructions, native continuation, and helper ABI. A semantic RAM role must be recovered independently per image, not derived by numerical address equality or firmware-family label. Revalidate bindings immediately before emission. Ambiguous/missing matches produce a structured blocker; they never fall back to a donor offset. Recognizers must cover the executable context needed for the proposed patch, not merely one comparison.

G01 evaluates the saved prior `di.state` before replacing it:

```
if state == 0xC7 || (state >> 2) == 0x32:
    accept attr in {0, 3}
else if (state >> 3) in {0x1D, 0x1F}:
    accept attr == 1
else:
    accept ((state & 0xC8) == 0xC8) || attr == 0
```

`attr` is DI bits5:4. The earlier universal attr0/3 rule both over-admits state00/attr3 and rejects stateE8/attr1. Limit the feature detour to the intended U/5/layers2-or3 scope, use the actual source state's cell, and preserve original replay on rejected or out-of-scope inputs. Native U/density1 support is outside this deliberately narrower detour and must remain explicit in coverage. Test prefix validation, wrong identifiers/density/layers and native normalization as well as the new predicate.

Native B19 is a newly inserted U marker; old B19 corresponds to native B1A mode, supported by four independent consumer grammars and reset code. Writing the marker at the old address corrupts another role. A private new marker without consumer changes also does not reproduce native behavior. Track the native marker's consumers as named unresolved dependencies, assess each by actual operation and counterpart, and add only demonstrated missing behavior. Absence from G01–G06 is not evidence that a dependency is irrelevant.

For earliest G03, the actual stock owner yields masked word `word & 0x4f0 == 0x430`, actual current candidate `0x400`, and native/BN11 `0x000`. These are same-owner reference observations, not register specifications. Independent inspection of `/tmp/freemkv-cross-astra-g03-owner.json` confirms native and BN11 full word0xfefffb0f, masked0x000. The execution audit's0x110 is a transcription error (compressed “BN11 0” misread), not a competing execution result. Use matching-entry owner execution as oracle. Repair the C7 handling of both bits7:4 and bit10 under the feature guard; replay every other original state/argument path. Widen qualification to both stores rather than asserting success at the first native continuation. Preserve unrelated bits according to each original RMW, and record intervening hardware reads as external behavior.

G04/G05 feed a normalized timing/control coefficient through a real common suffix to bounded hardware consumers including 0x04207508. Their physical units and hardware field names remain unknown. G05's old common suffix accepts supplied new intermediate values in 1,370 counterfactual sampled cases with zero normalized differences. This is affirmative reason to retain the old suffix, not proof of exhaustive equivalence or optical acceptance. Keep original measurement/status helper, denominator-zero handling, threshold bounds, reciprocal conversion, persistent stores and original return contract. The enclosing routine returns R5; reverse R6 is an internal coefficient.

G05 must distinguish C7's `mode != 0` from shared C8-class `mode == 1`. The old field is positively bound in 23 images; earliest is not yet bound. Existing old consumers support mode0/1, but current source evidence does not identify a nonzero producer/lifetime comprehensively. Native entry-to-stage CPU execution proves the argument0 path is feasible; the only established direct outer caller supplies argument1 and reaches resident code instead. No invented flash-to-resident alias is acceptable for 0x01f84482 or 0x01f83784. This uncertainty forbids blindly transplanting the native mode controller and also forbids declaring mode1 unreachable. Prepare the bounded detour and tests independently; close the source/resident lifecycle obligation before marking full old conversion complete. Physical read necessity is not a prerequisite to implementing that bounded software work.

## Atomic qualification and 171-source accounting

Maintain a manifest with one row per all **171** source entries, keyed by full hash and source identity; report duplicates explicitly rather than counting them as independent hardware outcomes. Each row carries G01–G08 observed contract, patch/retain decision, required semantic bindings, output hash, applicable profile, stage/owner/command CPU receipts, unmodeled boundaries and a terminal status. Missing execution is `not executed`, not pass. Zero patched sites is expected for retained native contracts.

Baseline inventory is **147 newer sources with six locally recognized media contracts**, plus **24 old plans currently blocked at G05** (23 already have local G03, one needs the expanded repair). The **121 isolated helper passes** are useful partial evidence, not 121 complete source conversions. The execution audit identifies 103,776 cases across those121 candidates: single-hook fixtures at fixed scratch space, some entered directly at helpers, stopping at first continuation/store/worker call; G05/G08 have no candidate execution branch. These are not full emitted outputs. Reconcile every source and actual stop boundary in the replacement manifest. Do not subtract unexecuted or malformed sources from the denominator to reach 100%.

Build every candidate in a transaction: discover and qualify all required contracts for its selected scope, reserve helper space without collisions, emit against verified originals, validate branches/literals/checksums/container, and only then expose a final candidate. Any required unresolved role returns no installable partial media conversion. Keep a reviewable failure manifest and intermediate research receipts; a planning manifest is not a flashable artifact. The complete-image gate must consume the actual emitted mod BIN, never a hand-reconstructed approximation of its stubs.

Two separate status dimensions prevent false completeness: (1) software qualification for the declared scope, and (2) observed hardware/host outcome. A software-qualified image can honestly have hardware `not tested`; this does not excuse leaving repairable software gaps unimplemented. Conversely, local test pass cannot set hardware success. A requested all-171 completion means all171 have a conclusive retained-or-converted software result for that exact scope, not simply 147 native plus24 excluded.

## Meaningful CPU gate and preservation

The implementation acceptance suite must reopen each actual mod BIN, validate its source/output hashes and installed hooks, map its own helper/code bytes, and run real entry paths as far as the artifact supports. Receipts identify every initial register/RAM input, intercepted call, modeled MMIO read, resident missing body and stop PC. Illegal memory, unexpected calls, unreachable continuation or changed native output fail the relevant contract; none count as skips that pass.

Exercise complete parser prologues/raw-buffer copies with actual pointer definitions, then normalization/error return; actual G02/G03/G06 owners through stores; and actual G04/G05 owners through old common consumers and return where code is available. Do not turn a manually imposed jump from DI into a selector into evidence of a real caller chain. Add command-level execution from real registered entries where binding permits; clearly stop at the first unmodeled acquisition/service boundary rather than fabricating success and calling the pipeline complete.

Matrices include all prior DI state classes and attributes, layers2/3 and invalid layers, C7/C8 plus ordinary/other states, mode0/1/nonzero, flag-clear/set, G06 indices0..12 and clamping, field high-bit preservation, arithmetic narrowing/wrap boundaries, measurement zero/timeout/nonzero, and supported/unsupported command formats. Test both real G03 callers' argument branches. Compare old original and mod behavior on feature Off, non-U inputs, DVD and ordinary BD/OEM paths; compare the intended C7 changes with native reference under equivalent logical inputs. Ensure ABI registers/flags, response lengths/errors, existing settings and boot defaults are preserved. Passthrough remains native; do not silently enable Encryption Off as a means of making a test pass.

Unicorn can establish exact executed instruction behavior, supplied-input reachability, argument/buffer changes and MMIO transactions under its memory model. It cannot prove optical acquisition, actual register latching/side effects, timing, unknown resident behavior, successful crypto or hardware acceptance. These limits belong in receipt schema and release wording. Hardware tests refine the second status dimension; they are not a blanket reason to defer the known predicate and selector repairs.

## Authentication and release scope

Expose an explicit requested milestone/profile in the planner and status output. Media classification, unprotected-sector reads, raw encrypted-sector access and factory AACS2 host playback are distinct outcomes. A G01–G06 success may say **media-path software conversion qualified**, never unqualified UHD/playback success. A raw-sector workflow may exclude G07/G08 only if its actual required command sequence is established; detection or VID success alone does not establish sector transfer or payload meaning.

Existing Encryption Off forces a rejected-certificate state and alters the READ DISC STRUCTURE 0xAD/format0x80 VID gate. It does not rewrite A3/A4 class routing, create the extended certificate/backend, or establish READ(10)/(12)/(16) data-phase success. Encryption On and Passthrough preserve native auth outcomes; default is Passthrough. Keep UHD feature settings distinct from encryption settings and preserve refusal behavior when UHD is Off.

For authenticated scope, G07/G08 native retention requires positive backend/mode compatibility, not an old/new family heuristic. Where G07 differs, bind and repair both REPORT selectors (including format0x38) and SEND selector together only with a compatible downstream backend. Test failed guards as well as supplied-success paths, actual buffers/canaries/length/error state, session reset and host allocation truncation. Increasing 116 to180 bytes without producing the extended content is not a repair. Authenticated completeness remains blocked where backend/resident/host contracts are unresolved, independently of media detours.

0.16.0 review should present concrete repaired software, the all171 manifest and bounded CPU outcomes, then list remaining source/resident and hardware/host uncertainties without claiming they were solved by helper counts. The current implementation remains on the research branch until the complete software qualification is established.

## Incorporated execution and G08 decisions

The execution review demonstrates that default Unicorn accepts Thumb2 MOVW while an explicitly configured ARM926 rejects it. Require ARM926 in every participating runner, including native fetched instructions, plus ISA controls that reject MOVW/B.W/CBZ/IT/SXTH/REV and permit genuine Thumb1 BL/BX. Instruction width alone is not an ISA validator. Test feature values0/1/2/255 and full MMIO single-bit/single-cleared-bit patterns. Use independently executed native behavior as the oracle; do not encode the candidate's disputed predicate or mask as expected truth.

Mutation tests operate on the actual emitted BIN: incorrect G01 predicate, wrong mode cell with opposing adjacent sentinel, adjacent G03 bit corruption, wrong helper slot/return PC, live-register/flag corruption, omitted restoration, wrong division worker, stale post-UHD state, unsupported ISA and unreachable hook must each fail a named assertion. A removed-marker mutation applies only to a contract whose native marker side effect is actually required/bound; it must not incentivize corrupting oldB19 to satisfy a generic checklist. A surviving applicable mutation blocks that contract. Report fetched-instruction and branch-edge coverage within explicitly bounded regions, never all-firmware path coverage.

Integrate the corpus gate into development and QA using the exact executable destined for release. Existing fixture jobs and promotion's artifact-name checks do not provide this binding. Require a receipt artifact with schema, successful status, expected fixed inventory digest, source/dependency commits, suite digest, shipping executable hash and every input/output hash; verify it in promotion and carry its digest into release provenance. `.github/` exemption from ordinary shipping-source comparison cannot exempt the qualification suite identity. Private full corpus may run locally/self-hosted with extracted distributable regressions in normal CI; those regressions cannot replace the full171 receipt. Fragments must bind to a verified full payload or remain blockers. Discovery totals outside the171 inventory are a separate metric.

G08 now has a concrete producer-to-staging chain in the native reference: acquired-header selector chooses mode; REPORT enforces mode/class agreement; certificate worker requires AGID<2 and session state3; it emits header0xb2/0x72, selects service0xb3/0x12, and copies144 bytes from0x1e9040 versus92 from0x1e8420. Response commit consumes capped180/116 transfer length, programs DMA address/count and marks ready, then the session advances to state4. These are source-observed operations, not a successful crypto/host trace. The protected backend bytes and service-range receipt do not establish backend semantics or provisioning. Forcing state6 neither supplies the earlier state3 precondition nor generates the extended response.

Therefore authenticated scope requires the connected SEND KEY/session/backend/content/transfer contract, not only G07 routing and a180-byte cap. Readiness and raw-sector independence remain unresolved until actual registered READ handlers are connected to session/mode checks and final transfer under OEM and Off settings, including failed key exchange, reset and disc-insert bus rearm. This missing software analysis is an actionable research/qualification task, not evidence that physical testing alone can resolve every gap.
