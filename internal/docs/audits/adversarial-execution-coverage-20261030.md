# Adversarial execution coverage audit, 2026-10-30

Scope: read-only review of existing qualification at firmware f5b7f12 and conversion dependency 66c4b1c, with a standalone Unicorn instruction experiment. This report does not certify later changes. Existing untracked `scripts/firmware_execution/` and `examples/firmware_execution_evidence.rs` were inspected, preserved, and not edited.

## Findings that prevent a full-conversion claim

The checked receipt records 103,776 ARM926 cases across 121 candidates. Those are candidate executions, not 121 fully converted images or complete G01–G08 paths. `test-mt1959-conversion-candidates.py` builds an in-memory single-hook modification at fixed scratch BASE=0x1e0000. G01/G07 execution starts directly at that helper rather than traversing the installed branch. Its isolated execution hook stops before the first native continuation instruction. Other roles use `audit-mtk-uhd-consumers.Runner`, which stops at the first passive-register write or native worker call. Thus a wrong continuation, clobbered live value consumed two instructions later, stale producer state, omitted marker, or overlapping simultaneously installed helper can evade these checks.

Concrete falsification cases:

* G01 initializes the media-state byte to zero in every `di_run`; prior DVD/BD/BDXL/UHD state, stale marker, and a failed subsequent DI parse are untested. Identity U, density 5, layers 2/3, attr 0/3 is asserted as accepted in the test itself. This embeds the disputed predicate in the oracle. Attr 4..15 is absent. New U-marker effects are not observed. Old-family marker address collisions require native producer execution, not an assumed independent marker write.
* G03 checks `word & ~0xf0`. The native producer/consumer contract must preserve or force adjacent bit 10 according to the native layout; the known early c88a case yields candidate 0x400 versus native/new-family 0x000 after masking 0x4f0 (corrected using the actual full-owner Astra receipt). Current words 0 and 0xa5a5a5a5 do not independently exercise each affected bit. A passing assertion against the candidate's own mask is not parity evidence.
* G04 selector tests assert only worker arguments `[0x1234,10]`. The separate numerical runner genuinely executes division but stops before the input-restoration STRH and observes only R6/SP. It does not establish that the caller restores its input, persists the correct output, or that reverse conversion consumes a mode produced by the actual G05 producer.
* G05 and G08 have no execution branch in the candidate test. G05 old B19 and new B1A semantic mode cells cannot be validated by writing a guessed common cell. G08 must have explicit native/no-change execution or explicit unsupported status; silent skipping is not completion.
* The candidate receipt hashes source files and candidate JSON, but not a real fully modified BIN. A correct helper fixture can pass while Modify installs a different helper or branches to a different slot.

## CPU adversarial experiment

With Python `/tmp/mt1939-recognition-venv/bin/python`, Unicorn 2.1.4, code `40 f2 01 00` (Thumb2 MOVW r0,#1), one instruction at 0x1001: default Unicorn ARM Thumb accepted it and set R0=1; explicit `ctl_set_cpu_model(UC_CPU_ARM_926)` rejected it with `UC_ERR_INSN_INVALID`. Several existing hook/runtime/frame/corpus-media runners instantiate default CPU without setting a model. The MT1959 candidate and numerical runners do set ARM926. Require the model and a fetched-instruction ISA check everywhere, including native instructions: legacy Thumb BL is a valid 32-bit pair and must not be rejected merely by instruction width. Use explicit negative controls for MOVW, B.W, CBZ, IT, SXTH, REV and permit Thumb1 BL/BX. Existing untracked CPU work already contains useful ISA/branch-coverage controls; it was not counted as integrated CI evidence.

## Executable qualification contract

Implement one corpus command consuming immutable input inventory, actual shipping Modify binary, and output directory. For each inventory image: verify input SHA256; invoke that binary to write the complete proposed BIN; verify output SHA256 and every reported installed branch, helper/table extent and native original bytes; instantiate CPU from those exact output bytes. Record binary SHA256, source/dependency commits, inventory SHA256, input/output hashes, CPU/Unicorn version and test-suite digest in each receipt. Never copy helper bytes into a separate fixture for this gate. Native/no-op images still execute native contracts. Mutation checks must alter the actual output BIN before execution.

For each G01–G08 row require one of: executed applicable contract; executed native/no-change contract; proven structurally not applicable with evidence; unsupported/blocker. Missing row, no reached checkpoint, instruction budget exhaustion, skipped unknown call, or uncontrolled memory access fails qualification. Record branch-edge and fetched-instruction coverage for explicitly bounded contract regions and each installed helper. Report uncovered edges; do not translate bounded coverage into all firmware/software path coverage.

Execute a chain of bounded real native stages, preserving memory and live registers between producer and consumer. Begin before DI identity/attribute/layer classification, execute native state/marker stores, then consumers, numerical worker and restoration, mode producer, reverse worker, parameter-table lookup and native continuation side effects. For external controller functions record exact ABI and model only the hardware return value; never replace a firmware arithmetic/decision worker with expected success. Check register liveness, NZCV where consumed, SP/LR, all RAM writes, passive MMIO address/width/value, table index bounds, and unchanged native behavior for Off/invalid feature values.

Minimum deterministic vectors:

* feature bytes 0,1,2,255; prior state 00,40,80,c0,c4,c7,c8,cc plus native marker values; both NZCV outcomes where branches use incoming flags.
* DI real/invalid prefixes; U/O/W/R/unknown identity; all density nibble values, all attribute nibble values, layer nibble 0..15. Include DVD, ordinary BD single/dual, BDXL triple/quad, UHD dual/triple, invalid and truncated DI; successful UHD followed by ordinary/failed DI must clear or restore exactly native state.
* G02/G03 words 0, all ones, each single bit, each single cleared bit, and mixed 0xa5a5a5a5/0x5a5a5a5a; assert full final register value against independently executed native semantic reference, especially bits 4..10 and bank address.
* G04/G05 unsigned 16-bit exhaustive input where practical, otherwise quotient boundaries 10k-1/10k/10k+1 plus 0/ffff and wrap bases; execute actual signed/unsigned worker semantics and restoration. Modes 0/1/ff at the discovered old/new cell; opposing sentinel at the adjacent B19/B1A cell proves the correct cell is read. Derive mode from native producer before downstream tests.
* G06 every valid table row and first out-of-range row, native table bytes, both flag branches; G07 full byte-domain class/format with native denial and acceptance downstream, not just helper exit; G08 all native state alternatives and consumer continuations identified by its actual contract.

Mandatory kill controls: current incorrect G01 predicate, removed new marker, G03 adjacent-bit corruption, old/new mode-cell substitution, wrong helper slot, wrong return PC, clobbered live register/NZCV, input-restoration store removed, swapped division worker, stale post-UHD state, Thumb2 instruction and unreachable branch. Each must fail a named assertion in a normal executable contract. A receipt lists the killed mutations and failing contract; surviving mutants block qualification.

## Scope accounting and dev → QA gate

Use the authoritative 171-image scope as a fixed hash set, not a dynamically filtered `supported` loop. Inventory separately tracks full payloads, duplicate hashes, fragments/containers and unknown/unidentified inputs. All 171 rows must reconcile to the hash set with no omissions or duplicates. Fragments cannot count as fully qualified payloads: bind them to an independently verified full payload or retain an explicit blocker. Broader discovery scan totals (including 885 unknown/partial inputs) are not the 171-image qualification denominator. Publish totals by family/layout and G01–G08; zero unsupported/blocker cells is required before saying all 171 are complete.

The inspected `qa.yml` runs independent CPU checks for existing hook/runtime/auth/media-related fixtures, but does not invoke the MT1959 candidate or numerical audits or require this full-output corpus contract. `promote_qa.py::eligible` checks run success and shipping artifact names only. Add a required CPU corpus job to development and QA, using exactly the build destined for QA. Upload the complete manifest/receipt and fail the workflow on unresolved coverage or a surviving kill control. Promotion must require the receipt artifact, validate its schema/result/expected inventory digest and shipping executable hash, and carry its digest into release provenance. Existing same-shipping-source checks should remain; `.github/` changes are currently exempt, so receipt suite identity must also be compared explicitly rather than assuming source comparison proves identical qualification. Keep the full private corpus local/self-hosted if redistribution is unavailable, and run legally distributable extracted regression fixtures in ordinary CI; fixture success alone cannot replace the 171-image receipt.

Completion means 100% of the explicitly enumerated contract obligations for the fixed corpus, or 0% eligible for a full-conversion release claim while blockers remain. It does not mean all possible software paths, physical optical behavior, authentication provisioning or drive hardware have been proved.
