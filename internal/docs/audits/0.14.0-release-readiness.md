# 0.14.0 release-readiness evidence

Checked on 2026-10-21 against the changes after tag `v0.13.4`
(`204974a903f7cc1411320d40abb3cf59c8c327bb`). This records software evidence;
it does not claim physical-drive flashing was performed.

## Published BU40N 1.00

The production Finder URL selects identity
`mediatek:HL-DT-ST BU40N BU40:GENERAL`, revision `1.00`. Its live HTML listed
seven packages: `0a47d1e6`, `2762f7cf`, `88a0ed80`, `b7ef4a97`, `d3b71fe3`,
`e696b7bb`, and `ed07c986` (SHA-256 prefixes).

Retrieved the corresponding TAR bytes from the site's `/fw/latest.tar.gz`
archive and checked each complete package SHA-256 and size against the Finder
catalog. All seven matched. Each passed the actual Modify CLI with `--audit`,
and the integration test exercised both its resulting TAR and extracted BIN
through the real Flash engine against an in-memory SCSI device.

The test asserts valid source/output CMAC, effective startup settings, structural
patch audit, refreshed package member digest, MediaTek routing, no writes or
backup in preview, validated rollback backup before execution, byte-exact target
transfer, update entry/finish commands, target startup and complete simulated
readback verification. It uses automatic receiver detection (`current: None`).

The committed OEM fixture SHA-256 is
`221ad35b7edd402353e125841893ce651064e8fc6b90368fe84ff19a85a506f4`, the image
inside published package `ed07c986`. Its round trip runs in ordinary CI; the
seven-package test additionally requires the downloaded private corpus:

```sh
cargo test -p freemkv-fw --test bu40n_flash_roundtrip
FREEMKV_BU40N_PACKAGES=/path/to/downloaded/packages \
  cargo test -p freemkv-fw --test bu40n_flash_roundtrip \
```

## Regression sensitivity against 0.13.4

Backported the new assertions to an isolated checkout of the exact release tag.
Only source compatibility was adjusted: the old `attach` signature lacks the
handler-length argument, and the old `FlashRequest` lacks `current`.

These tests compile and fail with the old behavior, and their production-tree
counterparts pass on 0.14.0:

- Unrecognized MediaTek TAR incorrectly recognized as Pioneer.
- Editable settings incorrectly require boot code to follow the injected handler.
- Legacy FreeMKV input receives the misleading missing coherent-table error.
- A previous production FreeMKV build receives the same misleading error.
- The Flash CLI rejects the newly supported `--current` option (argument-level
  feature check; the 0.14.0 receiver tests separately exercise its behavior).

The existing 0.13.4 CI was green. These are newly introduced regressions tests,
not evidence that the historical release CI was red.

## Review scope and gates

Reviewed shared workflow/CLI receiver-reference handling, file routing, handler
extent, GUI Current selection and frozen confirmation inputs, localization
catalogs/preferences and native menu refresh, and macOS bundle version stamping.
No additional product workflow was introduced during this readiness pass.

The full local workspace suite passed with `--locked --all-targets --all-features`.
Formatting and warning-free Clippy passed. Additional preference tests cover all
29 selections, session usability after a save failure, and cleanup/preservation
when atomic replacement fails. QA must additionally pass optimized tests on
Linux/macOS/Windows, native GUI gates, fixture authoring, cross-lint, and every
shipped release package/architecture before promotion to production.

## Remaining physical limits

Neither BU40N nor WH16NS58 1.V9 was physically flashed in this check. Mock
readback proves host behavior, not controller programming or USB/SATA transport
reliability. The real 1.V9 OEM reference plus modified target passed the separate
offline restricted-read receiver preparation test. Localization remains partial
as documented in the public release notes; operation details still include English.
