# 0.15.1 user error and guidance audit

Audit date: 2026-10-24. Scope: the shared `freemkv-flash::UserError` classifier, both optical backends, flash and recovery workflows, CLI output, Flash GUI, Modify GUI, and every embedded user-facing error catalog. This is a source and test audit; it does not claim physical-drive testing or native-speaker review of all translations.

## Presentation routes reviewed

| Route | User-facing sink | Error evidence retained | Disposition |
|---|---|---|---|
| CLI parsing and command failures | Localized `UserError` on stderr; help/version remain clap output | `diagnostics::run` chain; update progress when present | Parse failures carry `CommandOptions` and `NoFirmwareWrite`; operation failures share the same classifier as the GUI. |
| Flash and recovery workflow | Localized status/error result in CLI and Flash GUI | Typed `IssueCode`, `UpdateFailure`, backend error sources | All write outcomes retain the blocked, entry attempted, payload uncertain, temporary firmware, or unknown distinction. |
| Pioneer backend | `IssueKind` mapping plus typed corruption, current, settings, compatibility, and rollback errors | Kernel/Normal validation, receiver errors, phase/write evidence | The Normal-only installed Kernel mismatch now has a typed required/installed pair; the Kernel+Normal path is unchanged. |
| MediaTek backend | `IssueKind` mapping plus recovery/current/backup causes | Receiver, family, device and update evidence | Hardware mismatch uses the shared specific installed/selected message; write evidence takes precedence when the final result is uncertain. |
| Flash GUI workers and native shells | Localized status/failure cards and notices; native dialogs report their own failures | Worker events, `UpdateFailure`, diagnostics | The same issue ID and arguments survive worker delivery. A panic/disconnect while writing reports an uncertain result; a read-only worker fault reports no firmware write. |
| Modify GUI | Localized failure/status; diagnostic log retains the source chain | Artifact parsing, verification type, worker failure | Existing-image and generated-image integrity failures remain distinct. Modify operations carry the truthful no-drive-write consequence. |
| Localization | 29 embedded catalogs | IDs and placeholders | All catalogs have identical 637 message IDs and matching placeholders. Catalog parity is automated; translation quality has not received native-speaker review. |

## Typed classifier and consequence audit

| Evidence | User guidance decision | Audit result |
|---|---|---|
| `UpdateFailure::Blocked` | Preserve the specific typed cause and append `errors.update_blocked` | No-write statement comes from write evidence, not guessed from prose. |
| Entry attempted, zero payload | `errors.update_not_started` | Separates update-entry attempt from payload transfer; warns drive may remain in update mode. |
| Payload or final state uncertain | `errors.update_uncertain` | Does not claim either success or no write; warns firmware may have been written. |
| Temporary image may remain | `errors.temporary_firmware` | Tells user to keep connected and collect diagnostics before another update. |
| `HardwareMismatch` | `errors.hardware_mismatch` with installed and selected model arguments | Reworded to identify both firmwares as for different hardware and recommend a package compatible with the drive. Hash/family diagnostics remain private. |
| `InstalledKernelMismatch` | `errors.installed_kernel_mismatch` with required and installed tags | Added for Normal-only updates only; tells the user to choose a Normal compatible with the installed Kernel or a compatible Kernel+Normal pair. |
| `CorruptFirmware` | `errors.firmware_corrupt` | Typed cause beats internal detail; directs user to a fresh OEM copy. |
| `CurrentFirmwareRequired` | `errors.current_required` | Explains that installed firmware cannot be completely read/identified and requests matching Current firmware. |
| `BackupReadRestricted` | `errors.backup_restricted` | Explains this is expected for many MediaTek drives. |
| `UnsupportedFamilyOverride` | `recovery.family_override_unsupported` | Says the option is unavailable for this drive and directs user to compatible firmware. |
| `UpdateVerification` | `errors.verification_details` with selected/observed identity, Kernel, Normal, and startup states | Technical transport details do not replace the user-facing verification summary. |
| `InspectionError` variants | Format-specific unsupported/invalid, package-required, incomparable-pair, cancelled, and two-input guidance | Each variant has a stable catalog key. |
| File I/O | Not found, permission denied, exists, storage, timeout, or general access guidance | Uses the OS error kind only; raw path/source remains diagnostic data. |
| SCSI sense or unavailable backend | `errors.connection` | Transport details remain in diagnostics. |
| Unknown cause | `errors.unexpected` | No message-prose parsing is used to infer a more optimistic result. |
| Read-only operation | Append `errors.no_firmware_write` | Used only when entry point cannot write firmware. Backup guidance wraps the specific cause without losing this consequence. |

Pioneer and MediaTek map their optical library's `IssueKind` values consistently: invalid/unsupported firmware, receiver mismatch, hardware mismatch, connection, verification/update uncertainty, and unexpected. Pioneer preparation distinguishes unresolved settings from unsupported intermediate-transfer flows and reports startup rollback outcomes separately. The issue classifiers preserve typed causes through `explain`; boundary context supplies a fallback only when no recognized cause exists.

## Specific findings and changes

1. The normal-only compatibility refusal had the required and installed Kernel tags in diagnostics, but user guidance reduced it to a generic installed-firmware mismatch. It now carries typed `{required}` and `{installed}` values through CLI and GUI localization. Component headers are validated independently before comparison, so malformed Current/target errors keep their own cause and the error is not produced for an incoming Kernel+Normal pair. A regression test covers ID72 versus GENERAL, invalid-current/target precedence, and a complete pair replacing the old Kernel.
2. The `errors.hardware_mismatch` English text was indirect, and several translations had malformed label punctuation/wording. The message now directly states that installed and selected firmware are for different hardware, labels both identities consistently, and tells users to choose firmware compatible with the drive; all 29 catalogs were updated.
3. The settings and required-backup messages now explain the prerequisite in everyday terms and give the next step. Other backup, unsupported-device/firmware, and recovery messages were reviewed against their producers; no lost typed causes or false write claims were found there.

## Validation and limits

- Source inspected: `user_error.rs`, CLI parse/output, both optical `IssueKind` mappings, flash/recovery boundaries, Flash GUI worker/result paths, and Modify GUI operation/analysis paths.
- Automated local checks: focused mismatch/precedence/complete-pair tests; all application issue keys render in every language; catalog ID and placeholder parity script (29 catalogs, 637 keys); flash crate Clippy.
- CI/QA status is reported with PR #47 and the promotion record, not inferred from this audit file.
- No physical drive was exercised. `errors.unexpected` remains intentionally generic. Platform file-dialog and clap parser wording remains toolkit-owned. Translation parity and these author edits are not a substitute for native-speaker review.
