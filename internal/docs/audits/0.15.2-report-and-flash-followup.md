## UI and report policy

Retain typed transfer offset/length and structured sense through the MediaTek
adapter. Show the known block failure or communication cause together with the
existing entry/payload uncertainty, retaining independent verification fields.
Show a short failed-operation status and the full wrapped error once in results.

Check the stable GitHub release asynchronously at startup with an eight-second
bound. Only a valid newer stable release blocks automated submission. Failure,
invalid metadata, current or older releases allow normal reports. Show a persistent
localized update notice and enforce the gate both before prompting and sending;
local log viewing/saving remains available. This client gate takes effect in
0.15.2; it does not retrofit older binaries or change the report server policy.

After a fully verified flash, with no current failure or backup/dump attachment,
the existing send/cancel report confirmation explains that no errors were reported
and suggests website confirmation. The current URL opens the finder. No model-only
or revision-only inference is used to attribute a confirmation to another image.
Exact-content deep linking is not yet implemented.
