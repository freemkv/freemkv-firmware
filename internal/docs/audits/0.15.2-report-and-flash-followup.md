The original allocator injects code at 0x10470, inside unused CMAC-table entries.
The host verifier ignores instruction-valued flags, but the actual receiver tests
flag bit 0 and encounters a false active record: start 0x18B0B, end 0x18BE7,
stored digest at 0x104D0. Its alignment check fails and produces 05/26/02.
Re-signing cannot repair the overwritten descriptors.

`internal/scripts/wh_v9_integrity_repro.py` executes the original image's Thumb
integrity gate with Unicorn, modeling only AES-CMAC hardware and logging. It
reproduces the supplied image's rejection and accepts the rebuilt 0.15.2 image.
This is control-flow emulation, not a physical flash or programming-success test.

The replacement allocator subtracts codec-defined boot, mirror, integrity table,
identity and drive-written regions, plus BOOT digest/update signature storage.
It requires each aligned allocation to fit one active authentication range;
authentication ranges may overlap legitimately. It uses thumb-asm's deterministic
fit helper and scans the progressively modified image, so occupied bytes cannot
be allocated again. Existing whole-hole placements retain priority over clips.
Erased bytes alone do not prove arbitrary firmware code/data is unused; this
policy protects the known layout structures and does not claim full reachability
analysis of every firmware reference.

Rust red/green evidence: the WH descriptor-preservation regression fails with
the HEAD allocator and passes with the replacement. A separate erased-boot-mirror
regression fails with the prior table-only fix, then passes with the layout map.
Additional tests cover reserved storage, boundary clipping, exhausted space,
sequential allocations, CMAC coverage and metadata corruption in the audit.
The structural audit now checks table descriptors and entire unused entries,
independently of whether the output's recomputed MACs match.

## UI and report policy

Retain typed transfer offset/length and structured sense through the MediaTek
adapter. Show the known block failure or communication cause together with the
existing entry/payload uncertainty, retaining independent verification fields.
Show a short failed-operation status and the full wrapped error once in results.

Check the stable GitHub release asynchronously at startup with an eight-second
bound. Only a valid newer stable release blocks automated submission. Failure,
invalid metadata, current or older releases allow normal reports. Show a persistent
localized update notice and enforce the gate both before prompting and sending;
local log viewing/saving remains available. This client gate takes effect in
0.15.2; it does not retrofit older binaries or change the report server policy.

After a fully verified flash, with no current failure or backup/dump attachment,
the existing send/cancel report confirmation explains that no errors were reported
and suggests website confirmation. The current URL opens the finder. No model-only
or revision-only inference is used to attribute a confirmation to another image.
Exact-content deep linking is not yet implemented.
