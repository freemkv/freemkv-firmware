# Adversarial audit: G06 conditional nibble

Verdict: **UHD necessity unproven**. The observed code difference is real and conditional, and a source-matched change can reproduce the reference's register write. Neither that difference nor its distribution establishes that it is a UHD gate, that it occurs on a real UHD read, or that the alternative prevents a read. The register field and flag's physical meaning are unknown. The 147/24 classifications are based on this behavioral criterion, so treating the same correlation as independent proof of necessity is circular. Isolated helper execution proves those tested input/output contracts, not production reachability or optical behavior.

Addresses below are image offsets/Thumb addresses in original unmodified 2 MiB files. Reference BU40N 1.02 SHA-256 `1bbeb5351dc0d69feaeefdac9ada7f3f48eed0ca4e2f879d9266679cec133396`; old BU40N BN11 `5c01c1fda59f3db130bd14aa64fe97d4010376798716b16792dbffd59c488a95`.

Reference function entry `0xd8d2a`, state byte `0x01ff9e04`: `0xd8d34..38` admits all states with top two bits 11. `0xd8d44..54` accepts either `(0xc8 & ~state)==0` or exact C7. `0xd8d56..5c` tests bit 5 of byte `0x02000b11`. If set, `0xd8d5e..66` preserves upper bits and writes low nibble 2; otherwise `0xd8d68..78` uses the table at `0x14da2f`. The write is to `0x0420b1b8`, whose hardware semantics are not established. Old entry `0xd8378`, `0xd8392..9c` lacks the C7 acceptance; its bit test is `0xd839e..a4`, table path `0xd83b0..c0`, table `0x14c4eb`, same register address. When flag bit 5 is clear, C7 reaches the same table branch on both paths: G06 cannot alter this local outcome. These are local program counter claims, not an assertion that firmware revisions have otherwise identical code.

Both referenced tables' first 13 bytes are `4,4,4,3,3,3,3,3,3,2,2,2,2`. The index is `min((r0 >> 4) & 0xff, 12)` at reference `0xd8d3a..42` and old `0xd8388..90`. Thus old and reference also agree at indices 9–12 even when C7 and bit 5 are set, and differ at 0–8. This directly falsifies any claim of an unconditional change in C7 or that every flag-set call differs. Whether actual UHD production inputs occupy either range is not established.

Reference contains actual bit-5 producers, for example `0x6a046..4e`, `0xe0104..0c`, `0xe3a9e..a6`, `0xeb3ea..f2`, `0xf1b52..5a`, `0xf2230..38`, each loading the flag byte then ORing 0x20 and storing it. This proves the bit is not merely a synthetic emulator input; it does not establish these paths occur while C7 is active. At `0xe0104..0xe011a`, the set precedes a check that the media state's high nibble is C, but this alone does not prove C7 reaches the parameter call with the bit still set. Direct reference calls include `0x8b8f2`, `0x8bbc2`, `0x8bec2`, `0x8fc64`; the first three construct `r0 = 7*x` (`0x8b8ec..f0`, `0x8bbb6..c0`, `0x8beac..c0`), while the last passes r4. The upstream source and real ranges of x/r4, call path conditions, flag lifetime, and C7 coexistence remain unresolved. A raw Thumb scan is not a proof that these are the complete callers or that their decoding is reachable code.

A published investigation identifies U/5 disc-information layer nibble 2 as producing C7 and nibble 3 as C8; that supports C7 as a candidate media context, not proof of the downstream call/flag/index combination or successful UHD sector reading. C8 and other states satisfying the mask already use the same flag-conditional fixed nibble in both revisions, so this behavior is shared across state classes rather than intrinsically exclusive to UHD. The state-independent and media-selected *different* parameter getter in `uhd_parameter.rs` is not the G06 MMIO-nibble operation and cannot establish this field's function.

Falsification and next action: instrument the native reference through disc identification and acquisition, tracing state writes, flag setters/clearers, each call's r0, and the write to `0x0420b1b8`, across known ordinary BD, BDXL, UHD DL and TL media. First establish a real C7 + bit5 + index 0–8 occurrence; a trace with flag clear or index 9–12 is an explicit no-local-difference counterexample. Then on suitable physical hardware compare a validated baseline against an otherwise identical build with only G06 changed, observing acquisition and sector reads, multiple media and error telemetry. A repeatable failure cured by G06 in that controlled comparison would support conditional necessity for that case; successful reads without it would disprove universal necessity. Until such evidence exists label this a reference-conformance difference, not a required UHD gate. No flashing or hardware experiment was performed here.

## Downstream and production-input follow-up

The reference's direct call at `0x8b8f2` is **not** a C7 witness: `0x8b878..82` requires `0x02000b0b == 5` and `(state & 0xf7) == 0x51`, excluding C7. On that path r0 is 35 and index 2, but it would be incorrect to use that calculation to claim a reachable C7 difference. At `0x8bbc2`, r0 comes from seven times byte `0x02000b0b`; at `0x8bec2`, seven times r6; at `0x8fc64`, r4. For C7 the nearby sequence `0x8be1c..30` appears to cap r6 to 4 on its path, in which case `7*r6` gives index 0 or 1. The surrounding control-flow reconstruction and how that path enters the `0x8bec2` branch are incomplete; no C7 + flag-set call has been demonstrated. In particular no statement that arbitrary r0 values arise during media use is justified.

The output crosses an MMIO boundary at the actual `str` at `0xd8d78`, so plain memory emulation can prove a store but cannot prove the hardware observes, accepts, ignores, or acts on that value. An independent reference routine at `0xeae7e` **does read back** the complete word: `0xeae80..8a` calls the single-load accessor `0x46668` and saves it on stack; `0xeae96..a2` temporarily overwrites low five bits with `0x17` (low nibble 7); both `0xeaf42..46` and `0xeafb2..b6` restore the saved full word through the single-store accessor `0x4666c`. This shows a software save/restore consumer, not a software decision interpreting the nibble. It also shows that the write is not necessarily the final write; it does not establish that this routine follows the G06 call in any real C7 session or that the readback equals the written value on hardware.

Other reference code can overwrite that field: `0x79a92..9a` masks using `0xfffcfff0` and writes low nibble 2; `0xecf1a`, `0xed434`, `0xf4932`, and `0xf4b94` start direct read/modify/write sequences that likewise set the low nibble to 2. These local stores are not proven to follow the call in question. Conversely `0x747d2` reads and writes bits 27:24 of the same word while preserving the low nibble in the CPU calculation. These examples are not an exhaustive alias, indirect-access, or control-flow search. No identified code reads the G06 nibble to branch on its value, and no data sheet or device observation establishes a downstream hardware consumer or whether other configuration fields cause it to be ignored. C8's fixed 2 and the old table's 2 values prove the software can issue 2, not that a drive accepts it or that it is necessary for C7.

Next, recover the complete control flow around `0x8bec2` and `0x8fc64`, trace r6/r4 and every reaching flag-bit write on a C7 path, and capture the register transaction and following accesses in an actual execution trace. To resolve the MMIO boundary requires hardware documentation or instrumented hardware observation, followed by the controlled read comparison described above. Until then, the conditional reference difference is proven, but downstream acceptance and UHD necessity remain unproven.
